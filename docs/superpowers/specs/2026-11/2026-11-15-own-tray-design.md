# Власний значок у треї замість `pystray` (#119, #30)

Дата: 2026-11-15
Статус: чекає на затвердження
Spec-review: agy/gemini-3.8-flash @ 6c13985 (author: claude) — 6 findings: 6 fixed, 0 rejected

Друга з чотирьох специфікацій випуску в Store (рішення власника 15.11.2026 у [#119](https://github.com/ysilvestrov/obscura-text-writer/issues/119#issuecomment-6897352022)): «`pystray` (LGPL) — замінити власним кодом трея (Windows API)».

## Для власника

### Мета

У збірці Obscura не лишається жодної бібліотеки з ліцензією родини GPL, тож питання «чи виконано умови LGPL у пакеті MSIX, доступному лише для читання» знімається. Для людини значок у треї працює так само, як зараз. Після MCP цей значок — єдиний видимий слід Obscura, яку тихо запустив Claude.

### Що зміниться для тебе

- Юридичне питання LGPL з відомих обмежень SPEC зникає, і оцінювати його перед поданням у Store не треба.
- Збирання пакета зупиняється, якщо в збірку колись потрапить бібліотека з ліцензією GPL, LGPL чи AGPL. Тоді рішення знову за тобою.
- У ручній перевірці підписаного пакета (`manual.md#store-mcp-package`) додається крок: значок, меню, клік і «Вийти» у встановленій збірці. Автотести значка на справжньому треї не показують.
- Для запуску з вихідного коду на Windows більше не треба окремо ставити `pystray`: значок є одразу. Інструкцію встановлення на сайті (uk/en) буде оновлено.
- Що стає незворотним: нічого. Але повернути `pystray` можна лише новим рішенням: охоронець GPL зупинить збирання, і треба відновити вилучені частини збирання й вимогу PACKAGING-001-S03.

### На чому стоїть рішення

- `pystray` замінюється власним кодом на Windows API `[вимога власника]`.
- Значок, створений лише через `ctypes` (`Shell_NotifyIconW`, значок з PNG через `CreateIconFromResourceEx`, приховане вікно повідомлень), додається, приймає версію 4 і прибирається на цій машині `[проба]` (П1). Клік і меню проба не перевіряла: це доводить лише ручна процедура `[виведення]`.
- `pystray` — єдиний дистрибутив родини GPL серед 64 у залежностях збірки `[проба]` (П2).
- `pystray` уже повертає значок після перезапуску Провідника (`TaskbarCreated`) і відкриває застосунок одинарним лівим кліком; власний код має робити те саме `[проба]` (П3). Це виправляє моє твердження в чаті, ніби з `pystray` значок зникає.
- Pillow лишається в залежностях (малює значок і потрібна для обкладинок), тож значок без нової залежності `[виведення]`.

### Ключові рішення

1. **Власний модуль на `ctypes`, без нових залежностей** (вибір власника). Відкинуто `pywin32`: +~10 МБ, власні DLL у PyInstaller і MSIX заради одного значка.
2. **Поведінка значка лишається тією самою.** Те саме меню й мова системи; лівий клік відкриває застосунок, правий показує меню; значок повертається після перезапуску Провідника. Додано лише клавіатуру: протокол версії 4 дає «Enter» і клавішу меню на значку. Відкинуто «відкривати подвійним кліком»: так зараз не працює, і це змінило б звичку.
3. **Збирання відмовляє на бібліотеці родини GPL.** Без цього охоронця перехідна залежність тихо повернула б те саме питання. Відкинуто «просто прибрати `pystray`»: це не захищає від регресії.
4. **Помилка Windows API — як відсутній трей зараз.** Застосунок працює без значка й пише в журнал (DESKTOP-001-S04). Відкинуто «аварійне завершення»: Obscura, запущена Claude, має відповідати мосту й без значка.
5. **Значок лише на Windows.** Встановлена збірка існує тільки для Windows, а запуск з вихідного коду на Linux чи macOS — режим розробки. Там значка не буде (див. «Що стане гірше»). Відкинуто «лишити `pystray` для інших систем»: два шляхи коду й LGPL-залежність у середовищі розробки заради режиму, яким ніхто з користувачів не користується.
- Розглянуто стандартне: `pystray` чи `infi.systray` — відкинуто, бо перше LGPL (саме його прибираємо), а друге — ще одна стороння залежність без потреби (BSD, мало підтримується). Розглянуто стандартне: `pywin32` — див. рішення 1.

### Що стане гірше

- Свій код Windows API треба підтримувати. У `pystray` роки виправлень крайових випадків. Наприклад, після зміни масштабу екрана він перемальовує значок, а ми цього не робимо: значок може лишитися розмитим до перезапуску Obscura.
- Поведінку на справжньому треї перевіряє лише ручна процедура. Автотести ганяють логіку з підміненим API.
- Під час запуску з вихідного коду на Linux чи macOS значка більше немає (раніше `pystray` його показував). Застосунок працює, як із `--no-tray`.

### Оцінка

- Власник: S. Автор: S (план ≤ 4 задачі, один PR).
- Розбивка:
  - модуль трея й тести з підміненим API — ~50 %;
  - вилучення `pystray` зі збирання, охоронець GPL, `self_check` — ~20 %;
  - SPEC, traceability, ручні процедури, сайт uk/en, `docs/packaging.md` — ~30 %.
- Дешевше: без охоронця GPL (−~5 %), але тоді втрачається захист від повернення LGPL через залежність.

### Питання до власника

Немає.

## Тіло

### Проби

**П1 — значок на `ctypes` (15.11.2026, ця машина, Python проєкту).** Скрипт:
- реєструє клас вікна й створює приховане вікно (не `HWND_MESSAGE`: такі вікна не отримують широкомовного `TaskbarCreated`);
- з PNG 32×32, намальованого Pillow, створює значок через `CreateIconFromResourceEx`;
- `Shell_NotifyIconW(NIM_ADD)`, потім `NIM_SETVERSION` з версією 4;
- через 2 с з іншого потоку надсилає `PostMessageW(WM_CLOSE)`, цикл `GetMessageW` завершується, і значок прибирається.

Вивід: `{'atom': True, 'hwnd': True, 'hicon': True, 'added': True, 'version4': True, 'removed_after_destroy': True, 'events': [], 'taskbar_created_msg': True}`. Значок був видимий у треї. Клік і меню проба не перевіряла.

**П2 — ліцензії залежностей збірки.** `dependency_closure(root_requirements(pyproject.toml))` (усі extras збірки, 64 дистрибутиви) з пошуком `GPL` у `License-Expression`, `License` і класифікаторах. Знайдено один: `pystray | LGPLv3 … GNU Lesser General Public License v3 (LGPLv3)`. Залежності `pystray` на Windows: Pillow, `six`.

**П3 — поведінка `pystray._win32` 0.19.** `WM_LBUTTONUP` викликає типову дію, `WM_RBUTTONUP` показує меню через `SetForegroundWindow` + `TrackPopupMenuEx`, обробник `_on_taskbarcreated` повертає значок.

### Дизайн

**Модуль `storygen/win_tray.py`** (новий, лише Windows):
- оголошення `ctypes` з явними `argtypes`/`restype` для `user32`/`shell32`/`kernel32`, зібрані в об'єкт API, який тести підміняють;
- клас `NotifyIcon(api, title, icon_png, items)`:
  - `run()` блокує до виходу;
  - `close()` можна викликати з будь-якого потоку (`PostMessageW(WM_CLOSE)`);
  - `items` — список `(label, action)` з `desktop_tray.menu_items`, перший — типова дія.

Поведінка віконної процедури. Події значка приходять не окремими повідомленнями, а одним повідомленням зворотного виклику `CALLBACK = WM_APP + 1` (поле `uCallbackMessage`). Код події лежить у `LOWORD(lParam)`, а у версії 4 екранні координати значка — у `wParam` (`x = GET_X_LPARAM(wParam)`, `y = GET_Y_LPARAM(wParam)`, зі знаком для моніторів ліворуч чи вище основного):
- `CALLBACK` з `NIN_SELECT` / `NIN_KEYSELECT` → типова дія;
- `CALLBACK` з `WM_CONTEXTMENU` → меню: `CreatePopupMenu`, пункти з id від 1, типовий пункт жирним (`SetMenuDefaultItem`), `SetForegroundWindow`, `TrackPopupMenuEx(TPM_RETURNCMD | TPM_NONOTIFY …)` у координатах із `wParam` (не `GetCursorPos`: з клавіатури курсор миші може бути деінде), потім `PostMessageW(WM_NULL)` за документованою вимогою Windows, `DestroyMenu`; вибраний id → дія;
- інші коди `CALLBACK` (рух миші тощо) ігноруються;
- `TaskbarCreated` (через `RegisterWindowMessageW`) → `NIM_ADD` і `NIM_SETVERSION` знову з тим самим `HICON`;
- `WM_CLOSE` → `NIM_DELETE`, `DestroyWindow`; `WM_DESTROY` → `PostQuitMessage`.

`HICON` створюється один раз і звільняється `DestroyIcon` після виходу з циклу (і за невдачі запуску).

`NIM_DELETE` виконується ще й у `finally` навколо циклу, тож за винятку значок не лишається.

Розмір значка — `GetSystemMetrics(SM_CXSMICON)` на момент запуску; PNG малює Pillow (`desktop_tray._image`, той самий рисунок).

Підказка значка — «Obscura». Виняток у дії меню записується в журнал, а цикл працює далі. Будь-яка невдача:
- `RegisterClassW` (окрім «клас уже є»);
- `CreateWindowExW`;
- значка;
- `NIM_ADD` чи `NIM_SETVERSION` під час запуску (без версії 4 клавіатура й `NIN_SELECT` не працюють).

Кожна з них веде до `TrayUnavailable`, а значок (якщо доданий), `HICON`, вікно й клас прибираються.

**`storygen/desktop_tray.py`:** `run_tray(url, data_dir, backups_dir, stop)` зберігає підпис. Поза Windows (`os.name != 'nt'`) він одразу кидає `TrayUnavailable`. «Вийти» викликає `stop()`, потім закриває значок. `menu_items`, `system_locale` і `reveal` без змін; `pystray` більше не імпортується.

**`storygen/self_check.py`:** перевірка `tray` (назва лишається, `CHECK_NAMES` без змін) завантажує оголошення API (усі функції знаходяться в `user32`/`shell32`) і створює й знищує значок із PNG. Значок у трей не додається, бо самоперевірка не має нічого показувати.

**Збирання:**
- з `pyproject.toml` (extra `desktop`) прибирається `pystray`;
- з `packaging.pyinstaller_args` — `--hidden-import pystray._win32`;
- з `store_build/pyinstaller-hooks` — `hook-pystray.py`.

Нова `packaging.copyleft_distributions(names, *, lookup=distribution) -> list[str]` повертає дистрибутиви, у чиїх `License-Expression`, `License` чи класифікаторах ліцензії є `GPL` (охоплює LGPL і AGPL). `third_party_notices` відмовляє (`ValueError` «Бібліотека з ліцензією родини GPL у збірці: …») так само, як зараз відмовляє на `missing_licenses`, тож збирання зупиняється в тому самому місці, над фактичним складом збірки. `six` випадає із залежностей збірки сам, якщо його більше ніхто не тягне; повідомлення збираються за фактичним складом.

**SPEC:**
- DESKTOP-001-S04: GIVEN «запущений застосунок на Windows»; AND «поза Windows, у разі помилки Windows API або з `--no-tray`…»; новий AND про лівий клік, клавіатуру й повернення значка після перезапуску Провідника.
- PACKAGING-001-S03: останній AND замінюється на «дистрибутив з ліцензією родини GPL зупиняє збирання з його назвою».
- Модулі DESKTOP-001: трей = `desktop_tray` + `win_tray`, без `pystray`.
- Відомі обмеження п. 9: «Поза Windows або з `--no-tray` значка немає»; немає перемальовування після зміни масштабу.
- Відомі обмеження п. 10: речення про LGPL прибирається як усунене відхилення.
- Запис «Проби» DESKTOP-001 доповнюється пробою П1 (історичну пробу `pystray` позначити як заміщену).

**Документи:**
- `docs/verification/manual.md`: процедура DESKTOP-001-S04 без `pip install pystray`, з кроками «лівий клік», «меню правою кнопкою», «Enter на значку після Win+B», «перезапуск Провідника — значок повертається»; той самий короткий крок у `store-mcp-package`.
- traceability S04 і PACKAGING-S03 з новими тестами.
- Сайт `install` uk/en: замість кроку «встановіть `pystray`» — «на Windows значок у треї є одразу»; пара підтверджується `check_site.py --rehash install`.
- `docs/packaging.md`: рядок `tray` у таблиці самоперевірки, абзац про LGPL замінюється на охоронця GPL.

### Тести

- `tests/test_win_tray.py` з підміненим API, без справжнього трея:
  - запуск додає значок з `uCallbackMessage = CALLBACK` і ставить версію 4;
  - повідомлення `CALLBACK` з `NIN_SELECT` чи `NIN_KEYSELECT` у `LOWORD(lParam)` викликає типову дію; інші коди нічого не роблять;
  - `CALLBACK` з `WM_CONTEXTMENU` показує меню в координатах із `wParam` (зокрема від'ємних), у порядку пунктів з типовим жирним, і вибраний id викликає свою дію;
  - `TaskbarCreated` додає значок знову з тим самим `HICON`;
  - `close()` з іншого потоку прибирає значок, звільняє `HICON` і завершує цикл;
  - невдача `NIM_ADD` чи `NIM_SETVERSION` дає `TrayUnavailable` і прибирає значок, `HICON` і вікно;
  - виняток у дії не зупиняє цикл.
- `tests/test_desktop_tray.py`: тести меню й мови лишаються; тест з фальшивим `pystray` замінюється тестом з підміненим `NotifyIcon` («Вийти» — `stop()`, потім закриття); поза Windows `run_tray` кидає `TrayUnavailable`.
- `tests/test_packaging.py`:
  - `copyleft_distributions` знаходить LGPL у класифікаторі, GPL у `License-Expression`, не чіпає MIT;
  - у залежностях збірки немає жодного дистрибутива родини GPL;
  - аргументи PyInstaller без `pystray`;
  - тест hook `pystray` прибирається.
- `tests/test_self_check.py`: `importorskip('pystray')` прибирається; перевірка `tray` на Windows проходить без показу значка.

### Сумісність і міграції

Даних і форматів не зачіплює. У наявних середовищах `pystray` може лишатися встановленим, але не використовується. Поведінка `storygen-desktop --no-tray` без змін.

## Заявка → доказ

| Заявка | Де записано | Що доводить | Сила |
|---|---|---|---|
| Значок у треї є | рядок журналу «Сервер працює…» без попередження про трей | `Shell_NotifyIconW(NIM_ADD)` повернув TRUE (П1). Що значок видно, доводить лише ручна процедура | середня |
| Самоперевірка `tray` пройдена | звіт `--self-check` збірки | функції API знаходяться, значок з PNG створюється. Що трей показується, не доводить, і SPEC так не стверджуватиме | середня (заявка обмежена) |
| У збірці немає бібліотек родини GPL | збирання дійшло до пакета | `copyleft_distributions` над фактичним складом збірки з метаданих дистрибутивів (П2). Метадані декларує сам автор пакета | середня |
| «Вийти» завершило застосунок | `server.json` прибрано, журнал «Сервер зупинено» | наявний шлях `desktop._run` (`finally`), тест із підміненим `NotifyIcon` | сильна |

## Рев'ю спеки

| # | Перевірка | Рішення | Причина / що змінилося |
|---|---|---|---|
| 1 | Події значка приходять у `LOWORD(lParam)` повідомлення зворотного виклику, а не окремими `msg` | Виправлено | Дизайн і тести описують `CALLBACK = WM_APP + 1` з кодом у `lParam`; П1 позначено як без кліку й меню |
| 2 | Меню з клавіатури в позиції курсора миші | Виправлено | Координати з `wParam` версії 4, зі знаком |
| 3 | Невдача `NIM_SETVERSION` не веде до відмови | Виправлено | Входить в умови `TrayUnavailable` |
| 4 | Витік `HICON` | Виправлено | Один `HICON` на весь час, `DestroyIcon` після циклу й за невдачі |
| 5 | «Повернути `pystray` одним рядком» суперечить охоронцю GPL | Виправлено | Пункт про незворотність переписано |
| 6 | «Трей поза Windows не потрібен» видано за виведення | Виправлено | Тепер це ключове рішення 5 з відкинутою альтернативою |
