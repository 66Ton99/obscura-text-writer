# MCP «з коробки» у збірці Microsoft Store (#119, #30)

Дата: 2026-11-15
Статус: чекає на затвердження
Spec-review: agy/gemini-3.8-flash @ 371034a (author: claude) — 7 findings: 7 fixed, 0 rejected

Перша з чотирьох специфікацій випуску в Store (рішення власника 15.11.2026, записані в [#119](https://github.com/ysilvestrov/obscura-text-writer/issues/119#issuecomment-6897352022)). Інші три: власний трей замість `pystray`, сторінка «Платна версія» з формою списку очікування, решта #119.

## Для власника

### Мета

Людина без технічних навичок, у якої є Claude Desktop із підпискою, ставить безкоштовну Obscura зі Store, натискає «Підключити до Claude» і пише історію в чаті. Без консолі, без JSON, без API-ключа. Claude сам запускає Obscura, коли вона потрібна, сам веде людину від задуму до тексту й дає посилання, щоб читати й правити твір у вікні Obscura.

### Що зміниться для тебе

- **Перший крок (Крок 0) виконано 15.11.2026.** Подвійний клік по `.mcpb` у Claude зі Store не працює, а встановлення перетягуванням показує попередження про доступ «до всього комп’ютера». Тому за твоїм рішенням основний шлях для Claude Desktop — запис у конфігурацію, а `.mcpb` — запасний (поправка 1).
- **Наприкінці — ручна перевірка підписаного пакета** на твоїй машині: встановити, підключити Claude Desktop і Claude Code кнопкою, закрити Obscura, попросити Claude продовжити історію. Без цієї перевірки специфікація не вважається виконаною.
- **Obscura змінює конфігурацію Claude у двох місцях.** Claude Desktop — на основному шляху: дописує запис `obscura` у `claude_desktop_config.json` (з резервною копією поруч); запасний шлях (`.mcpb`) нічого не пише, установку робить сам Claude, коли людина перетягує файл у Settings → Extensions. Claude Code — офіційною командою `claude mcp add`/`remove` лише для запису `obscura`, без власного редагування файлів (копію не робимо: це штатна дія самого Claude Code).
- **У Store новий твір за замовчуванням у режимі «тексти пише чат»:** форма бібліотеки вибирає його сама, бо генерацію робить Claude за підпискою людини. Повне видання — як зараз.
- **Що стає незворотним:** нічого. Підключення знімається видаленням розширення в Claude або записом із конфігурації.

### На чому стоїть рішення

- Користувач — Claude Desktop із підпискою, без технічних навичок `[вимога власника]`.
- Історія починається й генерується в чаті, читається й правиться у вікні Obscura `[вимога власника]`.
- Якщо Obscura не запущена, Claude сам тихо запускає її у трей `[вимога власника]`; запущена так Obscura працює, поки людина не вийде через значок у треї `[вимога власника]`.
- Кнопка «Підключити» для Claude Desktop і Claude Code; інші клієнти пізніше за зразком `[вимога власника]`.
- Desktop: основний шлях — запис у конфігурацію, запасний — `.mcpb` перетягуванням у Settings → Extensions `[вимога власника]` (рішення 15.11.2026 після Кроку 0, поправка 1).
- Після підключення дві кнопки: «Перезапустити Claude зараз» і «Перезапущу сам» з поясненням про вихід через значок у треї `[вимога власника]`.
- Відмова межі видання в чаті пояснює платну версію й дає посилання `[вимога власника]`.
- Зараз міст MCP у пакет не входить: `EXCLUDED_MODULES` містить `storygen.mcp` і `mcp`, а `--noconsole` робить єдиний exe віконним `[проба: Зонд 1]`.
- Obscura вже вміє перевірити, чи запущений сервер цієї теки даних (`server.json` + `instance_id` через `/api/app-info`), і запуститися без браузера (`--no-browser`) `[проба: Зонд 2]`.
- Тека даних за замовчуванням `%USERPROFILE%\Obscura`, поза `AppData`, тож міст бачить `server.json` і поза контекстом пакета `[проба: Зонд 2]`.
- Claude Desktop зі Store тримає конфігурацію в `%LOCALAPPDATA%\Claude-Data\claude_<ідентифікатор>\claude_desktop_config.json`, і вона існує, поки Claude хоч раз запускався `[проба: Зонд 3]`.
- Консольний `storygen-mcp.exe` робочої копії, запущений Claude Desktop, не показує вікна консолі `[проба: Зонд 3]`; що так само поводиться консольний exe з пакета через псевдонім — `[виведення]`, перевіряє ручна перевірка пакета.
- `.mcpb` у Claude зі Store: подвійний клік не відкриває його (немає прив’язки типу файлу, Windows пропонує Блокнот); перетягування в Settings → Extensions показує вікно встановлення з попередженням «access to everything on your computer… not verified by Anthropic»; `mcp_config.command` з абсолютним шляхом поза розширенням приймається («All requirements met») і розширення встановлюється `[проба: Зонд 5]`.
- Псевдонім запуску (`uap3:AppExecutionAlias`) може вказувати на другий exe того самого пакета, і процес, запущений через нього, читає `%USERPROFILE%\Obscura` `[виведення]`. Перевіряє ручна перевірка пакета.
- Наш пакет MSIX може змінити наявний файл конфігурації Claude в `%LOCALAPPDATA%\Claude-Data` (зміни наявних файлів в `AppData` йдуть у справжні файли), але новий файл там Windows сховала б у приватну копію `[виведення]` — з дослідження `docs/research/2026-11-14-claude-skills-distribution.md` §2.5. Тому запасний шлях пише лише в наявний файл.
- Чи доступні розширення `.mcpb` на безкоштовному тарифі Claude, не перевірено; на цьому рішення не стоїть, бо цільовий користувач має підписку `[вимога власника]`.

### Ключові рішення

1. **Окремий консольний exe мосту `obscura-mcp.exe` у пакеті з власним псевдонімом запуску.** Відкинуто: режим `Obscura.exe --mcp` — віконний exe PyInstaller не має stdin/stdout для stdio MCP. Відкинуто: шлях у `WindowsApps\…_<версія>_…` — він змінюється з кожним оновленням.
2. **Міст сам запускає Obscura.** Якщо сервер теки даних не відповідає, міст запускає `Obscura.exe --no-browser` зі своєї теки й чекає готовності до 30 с. Адресу бере з `server.json`, тож зайнятий порт 8765 більше не потребує ручного `--url`. Відкинуто: автозапуск Obscura разом із Windows — постійний фоновий процес для всіх, а не лише для тих, хто відкрив чат.
3. **Claude Desktop — запис `obscura` у наявний `claude_desktop_config.json` однією кнопкою; запасний шлях — `.mcpb`, який людина перетягує в Settings → Extensions** (коли файлу немає або він пошкоджений). Відкинуто: `.mcpb` основним — у Claude зі Store він не відкривається подвійним кліком, а встановлення вимагає трьох дій у налаштуваннях Claude і показує лякаюче попередження (Зонд 5).
4. **Інтерфейс не каже «Підключено», якщо не може цього довести.** Для Desktop після запису він каже, у який файл записано і що зробити далі (перезапуск), а для `.mcpb` — що файл підготовлено й куди його перетягнути; для Claude Code стан перевіряє `claude mcp get obscura`.
5. **Відмови межі видання через MCP стають зрозумілими.** Міст замінює технічний текст межі (довга проза, серії, рейтинг) на пояснення «це можливість платної версії Obscura» і посилання `waitlist_url` зі збірки. Інтерфейс Obscura не змінюється.

Розглянуто стандартне: публікація розширення в каталозі Claude (Connectors Directory) — відкинуто, бо локальний сервер усе одно мусить бути встановлений на машині, а каталог додає модерацію й залежність від Anthropic; повернутися до цього можна після випуску.

Розглянуто стандартне: плагін Claude із MCP і скілами (R-35) — відкинуто для першого випуску, бо Desktop Chat ігнорує локальний MCP у плагіні (дослідження §2.3); скіли — наступний випуск.

### Що стане гірше

- **Пакет більший і збирання довше:** другий exe PyInstaller із залежністю `mcp`.
- **Obscura, яку запустив Claude, лишається працювати у треї**, поки людина не вийде через значок. Пам’ять зайнята й після закриття чату.
- **Основний шлях змінює файл іншої програми.** Пошкоджений JSON не переписуємо, а резервна копія лежить поруч. Якщо Claude змінить місце чи формат конфігурації, кнопка перестане працювати до оновлення Obscura; тоді лишається `.mcpb`.
- **Запасний шлях незручний:** людина сама відкриває налаштування Claude, перетягує файл і бачить стандартне попередження Claude про розширення поза каталогом.
- **«Перезапустити Claude зараз» закриває відкриту розмову**, зокрема ненадісланий текст. Кнопка це прямо каже.
- **Ризик сертифікації:** псевдонім запуску й другий exe — звичайні можливості MSIX, але Store їх ще не бачив у нашому пакеті.

### Оцінка

- Власник: XL (на всі чотири специфікації випуску); автор: XL на всі чотири, тож розбито на чотири специфікації.
- Ця специфікація, автор: **L** — 3–4 PR і ручні кроки власника поза репозиторієм.
- Розбивка: Крок 0 перевірка `.mcpb` — 10%; міст у пакеті, псевдонім, автозапуск, пошук порту — 35%; кнопки підключення й перезапуску — 30%; поведінка в чаті (межа видання, порядок роботи, режим «чат» за замовчуванням) — 15%; документація й ручна перевірка пакета — 10%.
- Дешевший варіант: без запасного `.mcpb`, лише запис у конфігурацію, а Claude Code — тільки показана команда. Втрачає людей без файлу конфігурації чи з пошкодженим файлом і додає одну ручну дію в Claude Code.

### Питання до власника

Немає. Відповідь власника 15.11.2026: Obscura, яку тихо запустив Claude, лишається працювати у треї, поки людина сама не вийде (без автоматичної зупинки за бездіяльністю, бо вона може обірвати фоновий етап).

## Пояснення для виконавця

### Зонди

1. **Пакет.** `src/storygen/packaging.py`: `EXCLUDED_MODULES = ('storygen.mcp', 'mcp', 'pytest', '_pytest')`; `pyinstaller_args` дає `['--noconfirm', '--onedir', '--noconsole', ...]`; `appx_manifest` має одну `Application Id="Obscura" Executable="Obscura.exe"` без розширень. `docs/packaging.md`: «У пакет не входять MCP-міст…».
2. **Запуск.** `src/storygen/desktop.py`: `RECORD = 'server.json'`, `PREFERRED_PORT = 8765`, `choose_port()`, `running_server(data_dir)` перевіряє `instance_id` через `/api/app-info`; `main` має `--no-browser`, `--data-dir`; `default_data_dir()` = `%USERPROFILE%\Obscura`. Міст (`src/storygen/mcp/bridge.py`): `DEFAULT_URL = 'http://127.0.0.1:8765'`, `--url`, `--client-name`; помилка з’єднання дає `ToolError('Obscura не запущено за адресою …')`.
3. **Claude на машині власника (15.11.2026).** `Get-AppxPackage *Claude*` → `Claude 5.11492.5.0`, `Claude_pzs8sxrjxfjjc`. Чинна конфігурація `%LOCALAPPDATA%\Claude-Data\claude_pzs8sxrjxfjjc\claude_desktop_config.json` (змінена 15.11), у `mcpServers` уже є `obscura` (ручне підключення з робочої копії); старіший `%APPDATA%\Claude\claude_desktop_config.json` (11.11). Claude Code: `C:\Users\yuriy\.local\bin\claude.exe`. У `%LOCALAPPDATA%\Microsoft\WindowsApps` є псевдоніми `claude-desktop.exe` тощо.
4. **Формат `.mcpb`** (`modelcontextprotocol/mcpb`, `MANIFEST.md`): обов’язкові `manifest_version`, `name`, `version`, `description`, `author.name`, `server`; `server.type ∈ {node, python, binary, uv}`; `mcp_config {command, args, env, platform_overrides}` з підстановками `${__dirname}`, `${HOME}`; `compatibility.platforms` (`win32`). Абсолютний шлях у `command` явно не описано.

5. **Крок 0 — `.mcpb` у Claude зі Store (15.11.2026, машина власника).** Тимчасові `obscura-probe-a.mcpb` (`server.type: binary`, `mcp_config.command` — абсолютний шлях до `storygen-mcp.exe` робочої копії, `entry_point` — копія запускача в розширенні) і `obscura-probe-b.mcpb` (команда `${__dirname}/server/storygen-mcp.exe`). Подвійний клік по A: Windows «Select an app to open this .mcpb file» (Блокнот, Word…) — прив’язки типу файлу до Claude немає. Перетягування A в Settings → Desktop app → Extensions: вікно «Obscura (перевірка A)… Install», попередження «Installing will grant this extension access to everything on your computer. Any developer information shown has not been verified by Anthropic», «All requirements met»; після Install розширення в «Installed on your computer» і в «Local MCP servers» поруч із ручним записом `obscura`. Роботу інструментів розширення не перевіряли: шлях через конфігурацію вже доводить ручний запис `obscura` (Зонд 3).

### Міст у пакеті

- Другий onedir-артефакт PyInstaller `obscura-mcp` (консольний), точка входу — `storygen.mcp.bridge:main`; `storygen.mcp` і `mcp` прибрати з `EXCLUDED_MODULES` лише для нього. Чи ділити `_internal` з основним exe — рішення виконавця (критерій: розмір пакета й простота `build_store.py`).
- Маніфест: `uap3:AppExecutionAlias` з `obscura-mcp.exe` на exe мосту. Ліцензійні повідомлення (`THIRD-PARTY-NOTICES.txt`) мають включити `mcp` і його залежності.
- Без аргументів міст: читає `server.json` теки `%USERPROFILE%\Obscura`; якщо `running_server` дає адресу — працює з нею; інакше запускає `Obscura.exe --no-browser` (сусідній exe пакета; у робочій копії — `storygen-desktop`, якщо знайдено) і чекає `running_server` до 30 с, потім `ToolError` з людським текстом «Obscura не запустилася; відкрийте її з меню «Пуск»». Явний `--url` поводиться як зараз (без автозапуску). Запуск ліниво — на першому виклику інструмента, а не на старті мосту, щоб Claude не піднімав Obscura просто тому, що відкрився.
- Якщо Obscura зупинили під час розмови, наступний виклик інструмента повторює пошук і запуск.

### Підключення (сторінка застосунку, у виданні Store і в повному)

- Блок «Підключити до Claude» з двома кнопками: Claude Desktop і Claude Code. Розташування — рішення виконавця (налаштування застосунку або перший екран бібліотеки, поки немає жодного підключення); у Store він має бути видимим без пошуку.
- **Desktop, основний шлях** (кнопка «Підключити Claude Desktop»): знайти наявний конфіг (Store: `%LOCALAPPDATA%\Claude-Data\claude_<id>\claude_desktop_config.json`, де `<id>` — з `PackageFamilyName` встановленого пакета Claude; інсталятор: `%APPDATA%\Claude\claude_desktop_config.json`). Можуть існувати обидва файли (Зонд 3: старий файл інсталятора лишився після переходу на версію зі Store). Пріоритет: встановлений пакет Claude зі Store → його файл; інакше файл інсталятора; обидва варіанти Claude встановлені — новіший за часом зміни файл, а інтерфейс показує, у який файл записано; зробити копію `claude_desktop_config.json.obscura-backup`; дописати чи оновити лише `mcpServers.obscura`, зберігши решту ключів і порядок; некоректний JSON не чіпати, а показати шлях. Команда запису — повний шлях псевдоніма `%LOCALAPPDATA%\Microsoft\WindowsApps\obscura-mcp.exe` (у робочій копії — шлях `storygen-mcp.exe`); вона не змінюється з оновленнями, тож запис не застаріває. Файлу немає — показати текст «Запустіть Claude Desktop хоч раз і повторіть» і запасний шлях.
- **Desktop, запасний шлях** (файлу немає, JSON пошкоджений або людина обрала «Інший спосіб»): сервер збирає `.mcpb` у `%USERPROFILE%\Obscura\claude\obscura.mcpb` (поза `AppData`; `server.type: binary`, `mcp_config.command` — та сама команда, `entry_point` — файл усередині розширення, `compatibility.platforms: [win32]`, версія = версія застосунку), відкриває теку з ним і показує покрокову інструкцію: Claude → Settings → Desktop app → Extensions → перетягнути файл → Install; попередження Claude стандартне для розширень поза каталогом.
- **Claude Code:** якщо `claude` знайдено — `claude mcp add --scope user obscura -- obscura-mcp.exe` (повне ім’я з `.exe`: Claude Code запускає процес без оболонки; запис, що вже є, — `claude mcp remove obscura` перед додаванням) і перевірка `claude mcp get obscura`; не знайдено — показати команду з кнопкою «Копіювати».
- **Перезапуск Desktop:** «Перезапустити Claude зараз» з попередженням, що відкрита розмова закриється; закрити процеси Claude Desktop і запустити знову (Store: `shell:AppsFolder\<PackageFamilyName>!<AppId>`; інсталятор: шлях exe). «Перезапущу сам» — пояснення: вийти через значок Claude у треї («Quit»), бо закрите вікно лишає Claude працювати, і відкрити знову.
- Усі тексти блоку — у каталозі `i18n.json` українською й англійською.
- Кнопки працюють лише з локального інтерфейсу (той самий захист походження запитів, що й решта POST); HTTP-маршрути не запускають довільних команд — лише фіксовані дії.

### Поведінка в чаті

- **Межа видання.** Міст розпізнає відмови `NO_LONG_PROSE`, `READ_ONLY`, `READ_ONLY_SERIES`, `EDITION_LIMIT` і межу читання MCP-BRIDGE-S16 за сталими текстами з `book/guard.py` і `rating/guard.py` (імпорт констант, а не копії рядків): `NO_LONG_PROSE`, `READ_ONLY`, `READ_ONLY_SERIES` — точним збігом, а шаблон `EDITION_LIMIT` із підстановками `{axis}`, `{n}`, `{max}` — регулярним виразом, зібраним із самої константи (кожна підстановка → `.+?`, решта екранована); тест перевіряє збіг на тексті, отриманому через `enforce_edition_limit` та повертає `ToolError` мовою твору, а коли твір невідомий — українською й англійською разом (рішення автора специфікації): що це можливість платної версії, що саме відкриває платна версія (довга проза, серії, без обмеження рейтингу) і `waitlist_url` зі збірки (порожній — без посилання). Сам сервер Obscura своїх текстів не змінює.
- **Порядок роботи.** `INSTRUCTIONS` і MCP prompt «Почати історію» (`start_story`) описують шлях: задум → `create_story` → шаблони → план і персонажі → сцени → посилання на твір у вікні Obscura (адреса твору з сервера), щоб людина читала й правила там. Наприкінці сцени чи твору Claude пропонує відкрити посилання. Наявні `next_steps` і `open_ghost_mode` лишаються.
- **Режим «тексти пише чат» за замовчуванням у Store.** Форма нового твору в бібліотеці у виданні Store вибирає `chat`; повне видання — як зараз. `StoryCreate.writing_mode` уже `chat` за замовчуванням.

### Інваріанти й сумісність

- Робоча копія без пакета працює як зараз: `storygen-mcp` з `--url` не змінює поведінки; без `--url` — новий пошук через `server.json` і автозапуск.
- Повне й платне видання отримують ті самі кнопки підключення (лише Claude Desktop через конфігурацію, якщо псевдоніма немає — шлях exe мосту з робочої копії).
- Міст не читає й не передає ключів; автозапуск не відкриває браузера.
- Запис у конфігурацію Claude змінює лише `mcpServers.obscura`.

### SPEC і traceability

Нова вимога в розділі MCP-BRIDGE або окрема `STORE-MCP-001` (рішення виконавця) зі Scenario: пошук сервера й автозапуск; межа видання з посиланням; Store — режим «чат»; запис у конфігурацію (вибір файлу, копія, лише `obscura`, некоректний JSON не чіпається); запасний `.mcpb` (склад маніфесту); Claude Code (команда й перевірка). Ручні процедури: встановлення підписаного пакета з підключенням обох клієнтів і автозапуском. Оновлення PACKAGING-001 (склад пакета, псевдонім, повідомлення про ліцензії), DESKTOP-001 (запуск від мосту) і сторінок сайту `mcp`, `install` (uk/en).
