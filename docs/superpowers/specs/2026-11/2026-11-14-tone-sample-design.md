# Тон прози за зразком літературного тексту (#76, R-31)

Дата: 2026-11-14
Статус: чернетка

## Для власника

### Мета

Автор задає звучання прози не лише описом у полі «Тон», а уривком літературного тексту. Письменник переймає з уривка ритм, лексику й будову речень, але не події, імена чи світ.

### Що зміниться для тебе

- **Нове поле «Зразок звучання»** у налаштуваннях письма твору, поруч із «Тоном». Один уривок до 3000 знаків, з лічильником. Зразок належить твору: в інший твір він не переноситься.
- **Хто бачить зразок.** Його отримують етапи, що пишуть прозу: чернетка, переписування за коментарями й редагування в режимі повного переписування. Він іде окремою секцією з позначкою, що це зразок звучання, а не сюжет. Завдання сцени (brief), план, пам’ять, редагування правками й оцінювач зразка не бачать.
- **Чат через MCP.** Зразок читається й змінюється в налаштуваннях письма, як «Тон». Контекст письма сцени має поле `tone_sample`, але лише тоді, коли зразок непорожній.
- **Зміна зразка не робить застарілими план, завдання й пам’ять.** Застарілими стають лише чернетки й тексти, які зразок бачили. Те саме стосується старих версій, збережених до цієї зміни.
- **Що стає незворотним:** нічого. Міграції бази немає: поле лягає в JSON версії стилю.
- **Твої дії:** затвердити специфікацію.

### На чому стоїть рішення

1. Зразок належить конкретному твору, а не бібліотеці застосунку. `[вимога власника]` (14.11.2026)
2. Зберігання — поле профілю стилю з окремою секцією в запиті (варіант 1). `[вимога власника]` (14.11.2026)
3. Зміна зразка не робить застарілими план і завдання сцени. `[вимога власника]` (14.11.2026)
4. Профіль стилю — версійний JSON; кожна зміна створює нову версію, і її ID — селектор `story/style_version_id` у знімках залежностей усіх етапів. `[проба]` (П2)
5. Профіль цілком як JSON іде в запити brief, draft, edit у режимі переписування й rewrite; memory й edit у режимі правок стилю не бачать. `[проба]` (П1)
6. Оцінювач отримує JSON стилю як канон. `[проба]` (П3)
7. Контекст письма MCP стилю не містить: чат бачить його через `get_settings`. `[проба]` (П4)
8. «Орієнтир фіналу» вже має таку саму схему: поле профілю, вилучене з JSON стилю, окрема секція з позначкою. `[проба]` (П5)
9. 3000 знаків — приблизно сторінка; цього досить, щоб передати ритм, і це не більше, ніж кілька відсотків вхідного обсягу запиту письменника. `[виведення]`

### Ключові рішення

1. **Поле `tone_sample` у профілі стилю, вилучене з JSON стилю, окрема секція лише для етапів прози.** Відкинуто окремий версійний матеріал зі своєю залежністю: новий тип, селектор і екран — M замість S.
2. **Сліпі до зразка етапи порівнюють стиль без зразка.** Для знімків `prepare`, `brief`, `patches`, `memory` і `evaluation` дві версії стилю, що різняться лише зразком, вважаються однаковими. Нового селектора немає, тож старі версії теж не застарівають. Відкинуто окремий селектор «стиль без зразка»: старі знімки його не мають, і перша ж зміна зразка зробила б застарілим усе, збережене до цієї зміни.
3. **Зразок бачать draft, rewrite і edit у режимі переписування.** Редактор, що переписує текст повністю, без зразка вирівнював би звучання. Відкинуто «лише draft».
4. **Один зразок до 3000 знаків.** Відкинуто кілька зразків: це вже бібліотека, яку ти відклав.

Розглянуто стандартне: стиль за кількома прикладами (few-shot), коли автор дає кілька уривків, — відкинуто для цієї зміни, бо один зразок у полі покриває запит, а кілька уривків потребують окремого матеріалу.

### Що стане гірше

- **Більше токенів** у кожному запиті чернетки, переписування й повного редагування, на розмір зразка.
- **Модель може переносити зміст зразка:** позначка «не сюжет» — підказка, а не гарантія. Застосунок цього не перевіряє.
- **Ручний текст сцени** (знімок `author_text`) теж стає застарілим після зміни зразка: цей самий знімок має MCP-чернетка, яка зразок бачить.
- **Порівняння стилю стає дорожчим:** для сліпих етапів, коли ID версії змінився, читаються дві версії стилю.

### Оцінка

- Власник: S. Автор: S, розбіжності немає.
- Розбивка: поле, секція в запитах, порівняння для сліпих етапів і межа — близько третини; налаштування, MCP і переклади — близько третини; SPEC, сайт двома мовами й тести — решта.
- Дешевший варіант: вписати уривок у поле «Тон». Коду немає, але немає позначки «не сюжет», уривок іде в brief і оцінювачеві, межі довжини немає, а зміна робить застарілим усе; відкинуто.

### Питання до власника

Немає.

## Модель

- `StyleProfile.tone_sample: str = Field(default='', max_length=3000)`. Порожній рядок — зразка немає. Довжина рахується за символами Python; пробіли на краях зберігаються як є, а «порожній» означає `not tone_sample.strip()`.
- Збереження — чинний `update_story_profile`: незмінний профіль не створює версії; CAS за ревізією твору.

## Запити

- `generation/context.py`: JSON стилю завжди без `tone_sample` (так само, як без `ending_goal`). Для `draft`, `rewrite` і `edit` поза режимами `patches`/`diff` непорожній зразок додається секцією `label('tone_sample', language)` після секції стилю:
  - uk: «ЗРАЗОК ЗВУЧАННЯ — НЕ СЮЖЕТ: ПЕРЕЙМИ РИТМ, ЛЕКСИКУ Й БУДОВУ РЕЧЕНЬ; НЕ БЕРИ ПОДІЙ, ІМЕН ЧИ СВІТУ»;
  - en: «VOICE SAMPLE — NOT PLOT: TAKE ITS RHYTHM, VOCABULARY AND SENTENCE STRUCTURE; NOT ITS EVENTS, NAMES OR WORLD».
- `brief` отримує JSON стилю без зразка. `memory` й `edit` у режимі правок стилю не мають, як і раніше.
- `evaluation/story_adapter.py`: документ стилю — JSON без `tone_sample`.
- Будівник промпту підготовки (`prepare`) стилю не читає; змін немає.
- Тексти ролей (`writer_*`, `editor_*`) не змінюються: позначка секції сама каже, як її використовувати. Відкрите для плану: чи потрібен рядок у системному промпті письменника; без реального виклику моделі це не перевірити.

## Залежності

- Скоупи, сліпі до зразка: `SAMPLE_BLIND_SCOPES = {'prepare', 'brief', 'patches', 'memory', 'evaluation'}`. Решта (`draft`, `prose_edit`, `author_text`, `author_rewrite`) зразок бачить.
- `storage/snapshots.compare_snapshot`: для селектора `story/style_version_id` у сліпому скоупі, якщо очікуваний і поточний ID різні й обидва не `None`, версії читаються, і зміною вважається лише розбіжність `StyleProfile.model_dump(exclude={'tone_sample'})`. Поява чи зникнення стилю (`None`) — зміна, як і раніше. Нечитна версія — `selector_unavailable`, як і раніше.
- Знімок не змінюється: селектор той самий, `refs` ті самі. Тому старі версії, збережені до цієї зміни, поводяться так само.
- Перевірка впливу (`impact/planning`) і відбиток контексту письма MCP беруть результат `compare_snapshot` або власний знімок; окремих змін не потрібно, але план перевіряє, що зміна лише зразка не дає завдань перевірки впливу для brief.

## MCP

- `mcp/bridge.WRITING_FIELDS` отримує `tone_sample`: `get_settings` показує його в `writing`, `update_settings(section='writing')` змінює. Відбиток розділу `writing` змінюється лише тоді, коли змінюється профіль.
- `application/writing_context._content` додає `tone_sample` лише за непорожнього зразка; інакше вміст і `context_fingerprint` ті самі, що до зміни.

## Інтерфейс

- Форма «Письмо» (`settings.html`): `<textarea name="tone_sample" maxlength="3000">` під «Тоном», підказка й лічильник «N / 3000». Збереження, «Скинути», брудний стан і захист виходу — чинні механізми форми профілю.
- i18n uk/en: мітка, підказка, лічильник.

## Специфікація й документація

- SPEC.MD: нова вимога `STYLE-SAMPLE-001` поруч із CONTEXT-005 (поле, секція, сліпі скоупи, MCP); сценарії й traceability.
- Сайт: сторінка налаштувань письма uk/en — розділ про зразок звучання з нейтральним прикладом (без авторського тексту під захистом).
- Реальний модельний виклик не виконується; приймання якості прози — дія власника за згодою.

## Проби

- **П1.** `generation/context.py:309-389`: етап `memory` повертає контекст на рядку ~371, `edit` у режимах `patches`/`diff` — на ~382, обидва до додавання стилю; решта (`brief`, `draft`, `edit` у режимі переписування, `rewrite`) доходить до рядка 385 і отримує `label('style')` з JSON профілю, без `ending_goal`, коли той непорожній (рядок 389).
- **П2.** `generation/dependencies.py:101`, `storage/snapshots.py:70`, `:376`, `:497` пишуть селектор `story/style_version_id` з ID версії стилю; `compare_snapshot` (`storage/snapshots.py:333`) порівнює `current != selector.expected`. `authoring/blueprints.update_story_profile` створює нову версію на кожну зміну профілю.
- **П3.** `evaluation/story_adapter.py:112`: `add(story.style_version_id, 'canon')` — текст версії стилю цілком.
- **П4.** `application/writing_context._content` (рядки 10–29) не читає стиль; поле `future` додається лише за непорожнього значення.
- **П5.** `generation/context.py:388-422`, `context_labels.py:39`: `ending_goal` вилучається з JSON стилю й іде окремою секцією «АВТОРСЬКИЙ ОРІЄНТИР ФІНАЛУ — ЗАДУМ, НЕ ЗДІЙСНЕНІ ПОДІЇ».
